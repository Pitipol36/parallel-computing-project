Why it is the best sequential version

Binned SAH build

the accepted standard for BVH quality, leaves of about 4 triangles

32-byte flat nodes

depth-first layout, left child implicit, two cache-friendly float4s

Ordered traversal

nearer child first; skip subtrees beyond the closest hit so far

Precomputed data

triangle edges for Möller–Trumbore, inverse ray direction for the slab test

Any-hit early exit

Tuned for one core

/O2 /arch:AVX2; swapping MSVC’s library fminf for compare-select made it 6× faster

5 · “Best” means the best known acceleration structure with single-ray traversal, deliberately single-threaded

The assignment compares sequential against parallel, so the baseline has to be as good as I can make a single thread. It uses the standard acceleration structure, a cache-friendly 32-byte node layout, ordered traversal with early termination, and precomputed triangle edges and inverse directions. One finding: MSVC compiles fminf into a library call, and replacing it with a simple compare-select made the CPU render and the BVH build about six times faster. Being honest about scope: SIMD packet tracing or wide BVHs would be faster still, but that is a different algorithm.
