Before the follow-up, a quick recap of where the first part left off. The BVH is what makes this possible at all: instead of testing all 871 thousand triangles, a ray on the dragon does about 45 box tests down a 26-level tree. The GPU then traces those rays 35 to 180 times faster than one tuned CPU core, with exactly the same tree. But that moved the bottleneck. The render now takes milliseconds, while building the SAH tree on one core still takes about 0.8 seconds, which is 97 percent of the time to the first image on the dragon. So the second part is about construction: can the GPU build the tree too, and how much tree quality does a fast build cost? I'll go from the fastest builder to the best tree: LBVH sorts triangles by position, PLOC and H-PLOC cluster them, TRBVH restructures the LBVH, and parallel reinsertion polishes any of them.
