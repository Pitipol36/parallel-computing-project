So far I timed the build and the render separately. Here is one stopwatch from start to finish: the mesh is in main memory, and the clock stops when the finished image is back in main memory. That includes uploading the mesh, every allocation, the build, the render with the optimized kernel, downloading the image and freeing the memory. H-PLOC gets to the first image fastest: 45 milliseconds on the dragon, against 808 for the CPU SAH build, which is 18 times sooner, and the same on the mixed scene. On all three million-triangle models it stays fastest at 4, 16 and 64 AO samples; only on the small bunny is the LBVH a little quicker. The fixed costs, uploading the mesh, allocating and downloading, add up to 16 to 19 milliseconds, which is more than H-PLOC's build itself. Parallel reinsertion does not pay for a single image: it adds 120 to 240 milliseconds of build and saves at most 64 milliseconds of render even at 64 AO. It pays off when the same tree is used for many frames. One more effect: during a several-second CPU build the GPU clocks down, so the first render after the full-sweep build is several times slower than normal. I woke the GPU before every timed run so that no builder pays for the one before it.
