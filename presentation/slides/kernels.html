For scale, one CPU core renders the bunny in 38.2 ms: brute force on the GPU is about 94× slower than the BVH on one core. Each version targets one bottleneck: algorithm, memory layout and access, then load imbalance.

For the ablation study there are four kernels behind a command-line flag. The bunny column is the small test where brute force is still feasible. Brute force takes 3.6 seconds, while the BVH kernels take about half a millisecond, and even one CPU core with the BVH takes only 38 milliseconds. So the algorithm matters more than raw parallelism. The naive BVH kernel uses the same tree but a plain array-of-structs layout. The optimized kernel uses aligned float4 loads through the read-only cache, a precomputed inverse direction and nearer-child-first ordering; it is about two and a half times faster on the bunny and three times on the dragon. The persistent-threads kernel launches only enough warps to fill the GPU and lets them grab tiles from a global counter; it makes no difference on either model.
